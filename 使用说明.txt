鲸鱼娘（蓝色大肥鱼）使用说明
核对日期：2026-10-31
适用范围：当前Windows项目；唱歌插件2.2.0、身份插件v0.2.0、聊天语音插件v3.2.1-whale、表情插件0.3.0、唤醒插件v0.3.0。

本文件是用户操作的统一入口，只描述当前功能、配置和限制。

【1. 日常启动与停止】

纯文字聊天：
1. 保持整个项目目录完整，双击「鲸鱼娘.bat」，选择「启动机器人」。
2. 首次启动可能联网安装依赖。等待启动日志显示平台连接完成，再到 QQ 私聊测试。
3. 浏览器打开 http://localhost:6185 管理机器人。
4. 机器人运行窗口需要保持打开，可以最小化。电脑睡眠或断网会影响在线状态。

需要音频功能时，在同一菜单中按用途启动：
  本地说话：GPT-SoVITS，127.0.0.1:9880，用于文字转语音。
  RVC换声：127.0.0.1:8001，用于唱歌、翻唱的人声换色。
  原创生成：ACE-Step，127.0.0.1:8002，用于原创歌曲生成。
高级菜单还可同时启动本地说话与RVC；不包含ACE-Step，也不自动启动机器人。
聊天语音选用MiniMax时，不需要启动本地GPT-SoVITS；按第6节配置云端密钥和音色ID。

已运行的服务不用重复启动。只用文字聊天，不需要启动这些音频服务。

停止机器人：在菜单选择「停止机器人」，或关闭机器人运行窗口。
停止入口沿用stop.bat，按根目录python进程筛选，可能同时结束使用该Python的音频进程；
其他音频服务需要分别在对应窗口按Ctrl+C并关闭窗口。

根目录只保留3个BAT：鲸鱼娘.bat为统一管理入口；start.bat、stop.bat保留给已有快捷方式、
自启动和更新重启使用。低频命令实现放在tools/commands/，不必逐个寻找或双击。
也可在项目根目录PowerShell直接执行：
  .\鲸鱼娘.bat start          启动机器人。
  .\鲸鱼娘.bat stop           停止机器人。
  .\鲸鱼娘.bat web            打开管理后台。
  .\鲸鱼娘.bat say            启动本地说话服务。
  .\鲸鱼娘.bat rvc            启动RVC换声。
  .\鲸鱼娘.bat music          启动原创生成。
  .\鲸鱼娘.bat progress       查看模型下载进度。
  .\鲸鱼娘.bat update         检查并应用内容更新。
  .\鲸鱼娘.bat status         查看本地服务端口。
  .\鲸鱼娘.bat guide          打开本说明。
  .\鲸鱼娘.bat --help         查看全部命令。
  .\鲸鱼娘.bat --check        只检查命令依赖路径，不启动或停止服务。
  .\鲸鱼娘.bat --dry-run rvc  只显示将执行的操作，不真正执行。
端口可连接只代表有服务监听，不代表模型已经加载或音频效果已经验证。

【2. 管理后台与首次配置】

后台地址：http://localhost:6185
初始用户名：astrbot（以当前实际账户为准）。
打包初始密码保存在 secrets/webui_password.txt；若已在后台修改，使用修改后的密码。
忘记密码时，先停止机器人，再在「鲸鱼娘.bat」高级菜单中选择重置后台密码；该操作会重新启动机器人，
留意启动窗口中的密码提示。

当前启动脚本使用根目录 secrets.env 加载配置。已有配置不需要重新填写。
首次配置可参考 secrets.env.example，主要项目如下：
  DEEPSEEK_API_KEY       默认聊天和搜索所需的 API Key。
  DEEPSEEK_MODEL         可选，默认 deepseek-flash。
  MINIMAX_API_KEY        可选，仅选用MiniMax聊天语音时需要；在本机填写，不写入人设或聊天。
  QQ_APPID、QQ_SECRET    QQ 官方机器人凭据；已有 WebUI 平台配置时可保留现有配置。
  OWNER_OPENID          可选，主人/管理员身份，按下面 /sid 返回的 UID 填写。
  SILICONFLOW_API_KEY    可选，用于默认的长期记忆嵌入模型配置。

密钥只在本机填写，不要发送到 QQ、截图或公开更新包。
正常启动会执行 configure.py，重新应用默认聊天提供商、人设及部分插件配置。
如果希望长期更换默认提供商或启动行为，需同时检查对应启动配置，避免下次启动被覆盖。

QQ 若提示公网 IP 不在白名单：
查看启动窗口显示的公网 IP，在 QQ 开放平台 https://q.qq.com 的机器人开发设置中加入
IP 白名单。公网 IP 变化后需要相应更新；同时确认机器人已获准在目标私聊/群聊中使用。

【3. 聊天、群聊唤醒与表情】

私聊可以直接发送消息。群聊明确 @机器人，或叫「鲸鱼娘、小鲸鱼、大肥鱼、蓝色大肥鱼」时正常唤醒，
不受随机概率和冷却限制；引用机器人消息及正常命令仍按框架规则处理。仅@全体按普通消息处理，不再强制唤醒她。
普通群消息只偶尔接话：当前主人消息10%、群友消息2%，同群距最近一次明确唤醒或随机接话触发
不足180秒时不再随机接话；冷却全群共享，明确叫她仍可回应。概率是每条符合条件消息的抽样值，
不保证固定条数或时间一定回复；冷却从触发时开始，不代表消息已送达，重载插件会清空计时。
仅提到DeepSeek，或单独说「戳戳、拍了拍」，按普通消息处理，不再强制叫醒；想逗她可先@或叫名字。
明确@其他人或引用别人消息的普通消息不参与随机接话。
她刚回复某人后90秒内，同一人接着追问（最多3轮）可直接接上，不必再@；对方说「拜拜」「先不聊了」等会结束跟进。
只是转述或讨论她（如「小鲸刚才说…」）不算叫她。平台未投递的消息无法触发，唤醒也不代表模型已完成回复。
相关入口：WebUI → 插件 → whale_wake，可调owner_probability、other_probability、
group_cooldown_seconds；两个概率都设0可只保留明确唤醒。other_mention_always当前为true，
poke_text_keywords当前留空，填入额外强制唤醒词会绕过冷却。
框架provider_ltm_settings.active_reply.enable保持关闭，由唤醒插件统一管理随机接话，正常启动会维持关闭，
避免叠加概率；群聊上下文记录保持启用。

表情由当前主模型自主选择，不是每次都发，也不会在模型选好后再随机否决。
素材与标签来自stickers/index.json。模型先用get_sticker_candidates查询少量候选，
阅读图片描述、已标注的适用/避用场景和文字，再用send_sticker选择具体图片ID。
普通聊天只携带简短标签与规则，不把142张图片或完整描述目录每轮送入模型；
选择表情时会增加主模型的工具交互，但不额外调用分类或视觉模型。
同一标签图片较多时（如「开心」），候选会优先排出图片其他标签在对方消息里出现过的那几张（如说到下雪就先给下雪的开心图）。

表情插件配置：
  enabled=true：允许自主发表情。
  cooldown_replies=3：同一会话的对话轮数间隔，多次工具推理不会额外计数。
  cooldown_seconds=60：同一会话的时间间隔；轮数与时间限制须同时满足，0可关闭对应限制。
  candidate_limit=4：每次最多返回4张候选，可设1～5张。
仅实际发送确认成功后才记录冷却和已发送图片；失败或取消不会当成已发图，也不自动重试。
每轮最多一张表情；允许文字加表情，语音与表情同轮只选一种附加媒体。
启用流式回复时，表情工具停用并要求模型使用文字，不输出隐藏标记；当前项目使用非流式。

成功工具结果会记录实际图片ID、描述和标签，保存在当前对话历史中，便于后续理解自己发过的图。
插件还保留当前会话最近5张图片的内存短记录，下次请求最多提供3条；重载会清空该内存记录，
长期可用情况仍取决于框架保留的会话历史。候选结果仅供选择，不表示已发送。
标签仅作精确或明确别名匹配，无法确认就不发。尾部标记兼容具体ID和仅对应一张图的标签；
多候选标签不代猜图片，未知或不完整标记会清理。正常对话应使用工具选择，不输出标记。
可用 /表情作者 查看署名。图中文字没有自动识别；visible_text未填写表示未核对，不代表没有文字。

需要搜索时可明确说：「先搜索再回答：今天有什么科技新闻？」
能否取得实时结果取决于当前模型、搜索配置和网络；失败时应按提示检查，不能把普通回答
当成已经完成联网搜索的证据。

【4. 主人身份与认识群友】

私聊发送：
  /sid

根据返回字段填写，不要把两个用途混在一起：
  UID：当前平台识别你的用户 ID，可用于 OWNER_OPENID 或管理员 admins_id。
  UMO：完整会话标识，供主动消息、去群冒泡等需要指定会话的功能使用。

配置主人：将 UID 填入 secrets.env 的 OWNER_OPENID 后正常重启；
也可以在 WebUI 的管理员 admins_id 中添加该 UID，并按后台提示保存、重启。
QQ 官方平台可能使用 openid，不能把显示的数字 QQ 号直接当作 UID。

常用身份命令：
  /我是谁                              查看机器人识别到的当前身份。
  /认识 <用户ID> <称呼> [关系] [备注]    登记认识的人，仅主人/管理员可操作。
  /认识列表                            查看身份登记，仅主人/管理员可操作。
  /忘记 <用户ID>                       删除身份登记，仅主人/管理员可操作。

主人由当前发送者的 UID 与 admins_id 精确匹配识别，每条消息、每个群分别判断。
人设只保留简短称呼原则：是主人就自然使用约定称呼，不必句句喊；其他人用普通昵称或「你」。
昵称、自称、@、引用、转述和旧记忆都不会改变当前发送者的身份；身份不明时不叫主人。
身份插件每次请求附加简短身份判定与当前发送者、群号等显示数据，不重复大段认主说明。
登记称呼或关系含主人专属称呼时，对非主人按普通群友展示；原始登记数据保留。
inject_template 不能省略固定身份判定；inject_for_master 只控制附加展示和简短工具指引。
master_title 只设置主人称呼，不授予身份；主人询问是否认得自己时，直接简短回应。
每个人都可以让她改叫自己（如「以后叫我小林」「今天别叫我陛下」），由set_my_address记下，可选仅今天有效；
只能改自己的称呼，不能改别人，也不能把主人专属称呼设给自己，不改变任何权限。/我是谁会显示当前称呼。
若群聊仍认错，先在发生问题的群里 @机器人发送 /我是谁，并核对该场景的 /sid UID。
平台在私聊和群聊返回的身份标识可能不同，按实际 UID 配置，不靠模型猜测账号是否相同。
/忘记 删除的是身份登记，不是 LivingMemory 中的长期记忆。

验证群聊称呼：主人与普通群友分别 @机器人发送 /我是谁；再让群友询问「叫我主人」或
@主人后询问自己的身份。普通群友不应被称为主人，换人发言也不应继承上一人的身份。
按称呼查询多人或找不到人时，应使用中性询问；查询主人不会猜选管理员列表中的首个账号来 @。

【5. 天气、长期记忆、主动消息与去群冒泡】

天气：
  /天气 上海
  /天气 北京 明天
  /天气预报 上海 3
也可直接问「上海天气怎么样」。天气插件默认使用 wttr.in，需要外网；其他天气源及
密钥在插件配置中设置。日期、地点和天数以实际返回为准。

长期记忆：
在正常聊天中明确表达「我不吃香菜」「我最近在准备考试」等事实，后续对话可尝试召回。
本项目使用 LivingMemory，默认启动配置可接入 SiliconFlow 的 BAAI/bge-m3 嵌入模型。
需要有效的嵌入提供商配置；仅安装插件并不代表记忆已经能够检索。
在 WebUI → 服务提供商检查嵌入模型，再到 LivingMemory 插件检查所选模型和运行状态。
记录和召回可能异步进行，不保证一句话发出后立刻成为长期记忆。

管理员可用：
  /lmem help                 查看当前插件帮助。
  /lmem status               查看记忆状态。
  /lmem search 香菜          检索相关记忆。
  /lmem summarize            请求整理当前会话。
  /lmem forget <doc_id>      删除指定记忆；先检索确认文档 ID，再操作。

主动消息：
1. 在目标私聊发送 /sid，复制完整 UMO。
2. WebUI → 插件 → 主动消息（Proactive Chat），把 UMO 填入私聊会话列表。
3. 配置自动主动消息、等待时间、免打扰时段和未回复上限，保存并按提示重载插件或重启。
4. 当前群聊定时主动发言关闭（group_settings.enable=false），已有目标会话保留；私聊主动消息配置保留。
   如手动启用群主动消息，还需要 QQ 平台允许，并受会话、权限和平台主动消息限制影响；
   它与群消息随机接话是独立入口，不受whale_wake的概率和180秒冷却限制。
未列入目标会话列表的私聊不会自动收到主动消息；已有本地配置以 WebUI 当前显示为准。
机器人不会仅凭聊天中的一句承诺就自动建立所有提醒；以插件实际配置及任务结果为准。

去群冒泡：
1. 在目标群 @机器人，发送 /sid，取得完整群 UMO。
2. WebUI → 插件 → 鲸鱼娘去群冒泡，按「别名=完整群UMO」配置目标群。
3. 主人私聊发送 /冒泡 群别名 大家晚上好。
仅主人/管理员可用；QQ 官方平台不能只凭数字群号投递，目标群还需允许主动消息。
重启后如提示找不到会话，可先在目标群与机器人说一句话，再重试。

扩展插件（第三方，随更新包安装）：
- 消息防抖（astrbot_plugin_debounce）：对方连续发几条没说完的话时，等说完（最多等6秒）合并成一条再回复。
  用本机小模型判断一句话是否说完（已下载在 data/plugin_data/astrbot_plugin_debounce/），send_threshold=0.6；
  WebUI → 插件 → 消息防抖 可关 enabled，或调 send_threshold（越高越爱等）和 timeout_seconds。
- 表情感知（astrbot_plugin_sticker_sense）：区分对方发的是表情包还是普通照片，引导自然接梗，
  不改人设。/sticker status 查看状态，/sticker toggle 开关。
- QQ 表情转文字（astrbot_plugin_qq_face_to_text）：把 QQ 小黄脸转成文字意思。官方机器人平台本身已把
  大部分表情转成「[表情:名称]」，这个插件主要做兜底，无需配置。
- 自主学习（astrbot_plugin_self_learning）：记录群聊用于学习说话风格、黑话和好感度，数据存在本机
  data/plugin_data/astrbot_plugin_self_learning/（SQLite）。当前设置：
    不会自动改写「鲸鱼娘」人设（auto_apply_persona_updates=false、auto_apply_approved_persona=false），
    学到的人设修改只进入待审查列表；关闭每日随机情绪；长期记忆交给 LivingMemory，不另存一份；
    回复前会附带学到的风格、黑话和好感度提示（enable_llm_hooks=true）。
  学习用 deepseek/deepseek-flash 分析，会额外消耗少量 DeepSeek 额度；默认每6小时、满50条消息才学习一次。
  管理页面：http://127.0.0.1:7833 （只限本机打开）；管理员命令 /learning_status、/affection_status。
  不想要时 WebUI → 插件 → self-learning 停用即可，鲸鱼娘的人设和记忆不受影响。

【6. 聊天语音：自主选择文字或语音】

聊天语音由 GPT_SoVITS 插件管理，支持本地 GPT-SoVITS 或可选 MiniMax。
speech_backend=gpt_sovits 沿用已有本地音色。先通过「鲸鱼娘.bat」启动本地说话服务，
再在 WebUI → 插件 → GPT_SoVITS 检查：
  enabled：启用。
  client.base_url：http://127.0.0.1:9880。
  default_params.ref_audio_path：存在且可由语音服务读取的参考音频。
  default_params.prompt_text、prompt_lang：与参考音频内容及语言相符。
如配置了专用 GPT/SoVITS 模型，也需确认模型文件存在。

私聊测试：
  /说 你好呀，我是大肥鱼。
  /说 （开心）今天也要好好吃饭呀。
也可使用命令别名 /gsv。

开头括号表示语气提示，不会作为正文朗读。实际情绪效果取决于已配置的情绪条目和
参考音频；未匹配时可能使用默认音色。
自主回复配置：
  auto.mode=model：默认，由当前主模型结合对话决定是否调用 gsv_tts；不会额外请求一个分类模型，
    也不使用 auto.tts_prob 随机决定。简短问候、安慰、鼓励、晚安可选择语音。
  auto.mode=probability：按 auto.tts_prob 将纯文本回复随机转语音；仍受内容与个人偏好限制。
  auto.mode=off：关闭自动及主模型工具语音；手动 /说 命令仍可用。
  auto.autonomous_max_chars=120：自主语音文本上限；代码、链接、表格、长回复或明确要求文字时用文字。
  auto.cooldown_sec=30：自主语音工具在当前会话中的冷却；群聊所有人共享，0可关闭。
  auto.max_msg_len：仅控制概率模式的纯文本转换长度。
人设只保留回复风格，插件每轮简短告知实际可选方式；可选语音时附上个人偏好和配置的字数上限。
文字偏好、当轮明确要求文字、关闭、流式或冷却时，直接提示主模型使用文字，避免无效语音调用。
流式输出时主模型使用文字，避免先发文字再发一遍语音；当前项目已关闭主模型流式输出。
语音合成或发送失败时尝试回退文字；同一轮最多发送一次语音，不重复确认或重发同一句。
模型应只传入回复正文，不朗读内心OS、动作或表情标记；开头语气括号仅用于选择语气。
工具结果已发送就不重复回答；正在处理就等待；尚未确认发送才用文字完成，不重试语音。
工具成功结果记录 spoken_text，随工具调用保存在当前对话历史，主模型能接着自己说过的话继续聊。
当前轮已选择或正在发送表情时，语音工具使用文字完成回复；已发送语音或文字回退后不再叠发表情。
这不是音频原生输入，也不会自动把任何语音识别为文字；接收别人的语音仍需配置并启用STT。

个人回复偏好：
  /语音模式              查看当前会话的个人偏好。
  /语音模式 自动         让她自行选择；默认。
  /语音模式 文字         当前会话对你只用文字。
  /语音模式 语音         当前会话对你优先考虑语音，仍遵守内容、冷却和服务可用性限制。
命令别名为 /回复方式，也支持 auto、text、voice。偏好按会话和发送者分别保存，
不会让一个群友改变整个群的偏好。自然语言「这次用文字」「不要语音」会限制当前这一轮；
长期偏好使用上述命令设置。
偏好文件为 data/plugin_data/astrbot_plugin_GPT_SoVITS/voice_preferences.json，不应手工填写用户ID。

MiniMax 为可选的云端语音合成，不需要启动本地9880：
1. 在MiniMax控制台准备可用的固定角色音色ID；插件不自动创建或复刻音色，也不上传录音。
2. 在本机 secrets.env 设置 MINIMAX_API_KEY 后正常重启机器人，使环境变量生效。
3. 插件配置 speech_backend=minimax；minimax.voice_id 填该音色ID，
   minimax.model 默认 speech-2.8-hd，minimax.base_url 默认 https://api.minimaxi.com；
   国际站可设 https://api.minimax.io。按账号所在站点使用对应密钥。
4. minimax.api_key_env 填密钥的环境变量名，不填密钥本身；minimax.timeout 默认60秒，范围1～600。
缺少密钥、音色ID或请求失败会回退文字，不会偷换音色或自动重试云端合成。
切换音色使用新的 voice_id；RVC模型与索引不能直接作为MiniMax音色ID。
语音识别属于另一项服务，当前项目STT尚未开启；MiniMax合成接口不负责将他人语音送进DeepSeek。

【7. 原创短歌】

用途：让大肥鱼根据主题或你提供的原创歌词生成一首短歌。
所需：ACE-Step（8002）、本地分轨器；要使用角色音色，还需启用 RVC 并运行8001。

私聊发送：
  /唱 一首温柔的晚安曲
  /唱 歌词 星光轻轻落在窗边，你的梦有微风相伴。

主题请求会先让聊天模型创作歌词；直接提供歌词可跳过主题作词。
也可自然地说「给我唱一首考试加油歌」，但自然语言入口还依赖当前人设和模型工具调用。
首次排查优先使用 /唱 命令。

当前流程：生成完整歌曲 → 分离人声和伴奏 → RVC 只处理人声 → 混回原伴奏 → QQ 语音。
默认时长30秒，工具支持15～60秒；时长和超时可在鲸鱼娘唱歌插件配置中调整。
原创生成默认使用 CPU；分轨只使用 CUDA 显卡，首次请求还会加载模型。
同一时间只制作一首。收到「开始制作」只表示任务已开始，请等语音结果或明确错误，
不要反复提交同一请求。

已有简谱也可以使用当前支持的曲谱入口：
  /唱 demo
  /唱 歌词 | 简谱
简谱模式使用本地 DiffSinger，不需要8002；要换成角色音色仍需RVC。
demo 仅验证简谱模式，不能替代原创生成模式的测试。

作品保存在 data/temp/whale_sing/song_*/，其中：
  generated_mix.wav     原创生成的完整歌曲。
  vocals.wav            分离或直接合成的干人声。
  instrumental.wav      对应伴奏。
  rvc_vocals.wav         启用 RVC 时的角色人声。
  final.wav             最终混音。
  qq_preview.wav        用于 QQ 发送的预览音频。

【8. 原曲翻唱：AI点歌（matsuko_cover）+ 本地翻唱网关】

翻唱由「AI点歌」插件（astrbot_plugin_matsuko_cover）负责：点歌、搜歌、上传音频翻唱都走它。
它调用本机翻唱网关 127.0.0.1:3333，网关复用原来的分轨（BS-Roformer，CUDA）和 RVC 换声（8001，胡桃音色），
所以音色、分轨质量与原来的 /翻唱 相同。唱歌插件自带的 /翻唱、/翻唱列表 和 whale_cover 工具当前关闭
（whale_sing 配置 cover_enabled=false），避免两个翻唱功能抢同一句话；原创 /唱 不受影响。

使用前：
1. 用「鲸鱼娘.bat」启动 RVC 换声；RVC 窗口会顺带最小化打开「CoverGateway-3333」翻唱网关窗口。
   也可单独运行 voice-backends/cover-gateway/start_api.bat。两个窗口都要开着。
2. 直接说「翻唱一首晴天」，或用命令：
     /qqrvc 歌名      从QQ音乐搜歌后翻唱（按序号或按钮选歌、选音色）
     /rvc 歌名        用默认音乐源搜歌后翻唱（当前 default_api=qqmusic，即QQ音乐）
     /本地翻唱        对最近发的语音/音频文件翻唱；发音频时文字带「翻唱/转换/变声/修音」会自动触发
     /翻唱帮助        查看全部命令；/刷新rvc模型 重新读取音色列表；/查看翻唱任务、/取消翻唱任务
3. 音色列表来自 voice-backends/RVC/models/*.pth，胡桃的别名是「胡桃」。

限制：
- 只能下载免费歌曲（QQ音乐；把 default_api 改成网易云时同样只限免费歌）；VIP/无版权歌曲会提示失败，可改为上传音频文件。
  插件配置 third_party_api_key（jkapi.com）可补充付费歌曲链接，需自行注册，默认留空。
- 长于5分钟的歌只取前5分钟；本地音频默认上限20 MB。
- 同一时间只做一首，后提交的排队；原创 /唱 与翻唱同时进行会抢显存（6 GB），尽量错开。
- 缓存位于 data/temp/whale_sing/cover_gateway_cache/，同一首歌、同一音色和升降调会直接复用。
- 翻唱商业歌曲请只做个人娱乐，不要公开传播。

恢复旧的唱歌插件翻唱：WebUI → 插件 → whale_sing 把 cover_enabled 改为 true，
同时在 WebUI → 插件 中停用「AI点歌」，然后重启机器人。

【9. 音频模型准备与下载查看】

已有环境和模型可直接使用，不必每次重新安装或下载。
从未准备生成/分轨环境时，在项目根目录 PowerShell 执行：
  powershell -NoProfile -ExecutionPolicy Bypass -File .\voice-backends\music-generation\setup.ps1 -DownloadModels

仅补齐模型时：
  powershell -NoProfile -ExecutionPolicy Bypass -File .\voice-backends\music-generation\setup.ps1 -ModelsOnly

查看当前模型文件和下载进度：在「鲸鱼娘.bat」中选择下载进度，或执行 .\鲸鱼娘.bat progress。
它只显示状态，不会发起下载。不要同时开启多个下载器。
更详细的安装、补齐下载和运行参数见 voice-backends/music-generation/README.md。

显卡分轨安装命令（在项目根目录 PowerShell 执行一次）：
  powershell -NoProfile -ExecutionPolicy Bypass -File .\voice-backends\music-generation\setup.ps1 -SeparatorOnly -SeparatorDevice cuda
这会建立独立的 separator-cuda/.venv，不修改机器人或 RVC 环境，复用已有分轨模型。
安装需要下载 CUDA 依赖。唱歌插件配置：
  separator_device=cuda：只使用显卡；CUDA 不可用或显存不足直接报错，不回退 CPU。
  separator_segment_size=401：约4秒片段，可设129～801；801约8秒，显存需求更大。
  separator_python：一般留空，选择独立 CUDA 环境；自定义路径也必须支持 CUDA。
CUDA 分轨使用 FP16，重叠数沿用模型配置；片段大小可能影响接缝与上下文表现，调整后应试听。
分轨进程退出后再进行 RVC 换声，释放分轨自身显存；其他程序的显存不会自动释放。
更改设备、片段大小或模型 YAML 后会重新制作对应缓存；不需要更换 RVC 音色模型。

RVC 模型路径、索引路径与开关在鲸鱼娘唱歌插件配置中维护：
  rvc_enabled、rvc_base_url、rvc_model_path、rvc_index_path。
RVC 换声使用独立的 rvc_timeout_sec，默认1800秒；它不决定分轨速度，也不改变音色参数。
本地 RVC API 默认关闭 CUDA Graph 缓存，仍使用显卡推理，避免不同歌曲长度的捕获缓存占用大量内存。
修改RVC API后需单独关闭其服务窗口，再通过「鲸鱼娘.bat」启动RVC换声；服务启动不等于音色模型已加载。
请保留正在使用的有效音色模型，不要为测试覆盖或重训它。
与原伴奏混音时 rvc_f0_up_key 应为0；只改变人声调性会与伴奏不一致，插件会明确拒绝。
健康接口可访问只代表服务可连接，不代表模型已加载或歌曲质量已经验证。

【10. 人设、插件修改与模型输入】

人设只日常维护两份文件：
  persona/system_prompt.txt       身份、性格、说话方式、群聊、记忆和唱歌规则。
  persona/safety_addendum.txt     补充边界与如实使用工具的规则。
加载说明见 persona/README.md。

正常启动时，会把主设定、补充边界和表情包规则写入数据库中的「鲸鱼娘」人设。
保存文本不会立即刷新正在运行的机器人；修改后按正常流程停止并重新启动。
只在 WebUI 修改人设，可能在下次启动时被源文件重新覆盖。

插件源代码在 plugins_src/，启动时同步到 data/plugins/。需要长期修改插件时优先改源目录，
不要只改运行副本。仅重载插件能否生效，取决于运行副本是否已经同步。

普通聊天的每次主模型调用都会带一份当前人设；工具调用后的再次推理也会携带。
正常流程不会把这份人设逐轮累积成多份。历史、记忆和工具说明也可能增加输入量。
当前人设加载仍以文字为主；仅把立绘、录音放进 persona/ 不会自动送入模型。

【11. 开机启动与更新】

开机登录后启动机器人：在「鲸鱼娘.bat」高级菜单选择开启自启；取消时选择关闭自启。
这不等于开机自动启动全部音频后端，音频服务仍按需要启动。

立即检查并应用内容更新：在管理菜单选择内容更新，或执行 .\鲸鱼娘.bat update。
机器人正在运行且文件发生变化时，更新脚本可能重启机器人；有未完成音频任务时先等待结束。
仅检查远端更新而不应用：执行 .\鲸鱼娘.bat check-update；这与--check的本地命令路径检查不同。
启用每日自动更新：在高级菜单选择开启自动更新，注册每天04:30的Windows计划任务；
关闭每日任务时选择关闭自动更新。启动脚本自身仍会检查已配置的更新源。

更新需要有效的更新源和签名公钥。未配置或无法取得有效清单时会跳过，按日志排查。
当前自动更新白名单包括 stickers/、persona/、plugins_src/、configure.py 和使用说明.txt；
不会通过该白名单覆盖 secrets.env、secrets/ 或 data/。
本说明由签名更新包提供时会同步替换为当前内容，不追加版本历史。
本地修改的人设或插件可能被更新包中的同名文件覆盖。
更新详情入口：自动更新说明.txt；检查日志：logs/updater.log。

【12. 最小测试与常见问题】

按需要逐项测试，无需一次启动所有后端：
1. 聊天：私聊「大肥鱼，你好」，确认能正常回复。
2. 身份：发送 /sid 和 /我是谁，核对 UID、UMO 和识别身份。
3. 天气：发送 /天气 上海，确认城市与数据时间。
4. 说话：启动9880，发送 /说 你好呀。
5. 原创：启动8001、8002并确认分轨环境就绪，发送 /唱 一首温柔的晚安曲。
6. 翻唱：启动RVC（会同时打开3333翻唱网关），发送 /qqrvc 一首免费歌曲，或发一段短音频并说「翻唱」。

打不开后台：确认机器人运行窗口仍在、启动没有报错，地址为 http://localhost:6185。
提示6185已占用：可能已有机器人在运行，不要重复启动；先检查现有实例。
群里不回复：先 @机器人，检查 QQ 权限、平台投递和唤醒插件设置。
群里插话太多：检查whale_wake的两个概率与冷却，保持框架随机主动回复关闭，并检查群定时主动消息是否被启用。
认主错误：检查 /sid 的 UID 与 admins_id/OWNER_OPENID，保存后正常重启。
记忆不工作：检查嵌入提供商、LivingMemory 配置和实际运行状态。
语音不工作：先检查speech_backend；本地后端检查9880、参考音频、参考文本和模型路径，
MiniMax检查密钥环境变量、所选站点和固定voice_id。尚未配置时只会文字回退，不代表语音已就绪。
自主语音始终用文字：检查个人/语音模式、auto.mode、流式设置、内容长度和冷却；
auto.tts_prob只影响概率模式，自主选择也不保证每条消息都发语音。
唱歌提示连接失败：按提示分别检查8001换声服务或8002生成服务。
分轨完成后换声超时：检查 RVC 服务日志及 rvc_timeout_sec；整首歌的换声可能超过180秒。
翻唱提示连不上后端：确认「CoverGateway-3333」窗口和 RVC 8001 都在运行。
翻唱提示下载失败：多为VIP歌曲，换一首或直接上传音频文件。
生成很慢：首次加载与 CPU 推理可能耗时较长；查看服务窗口，等待结果，不要重复提交。
翻唱分轨很慢：检查 CUDA 环境和插件版本；separator_python 一般留空，separator_device 设为 cuda。
显存不足时减少其他显卡任务，或适当减小 separator_segment_size 后试听，不会自动改用 CPU。
WHALE_MUSIC_DEVICE 只控制原创生成服务；分轨由 separator_device 控制，增加超时不会加快计算。
自然语言不会唱但命令可用：检查当前加载人设及模型工具调用，正常重启以应用源文件。
服务窗口显示成功却没收到 QQ 语音：分别试听生成目录中的结果，再检查 QQ 平台发送错误。

反馈问题时提供所用命令、相关服务窗口的错误和脱敏后的日志，不要附带密钥或完整凭据。
